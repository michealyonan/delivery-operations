# منظومة إدارة التوصيل

تطبيق عربي بثلاثة أدوار: الإدارة، المطعم، والمندوب، ويعمل على Android والويب. الطلبات والموقع المشترك يحتاجان اتصالًا بالإنترنت وقاعدة Supabase.

## تشغيل المعاينة

1. ثبّت Node.js LTS.
2. نفّذ `npm install`.
3. لتشغيل نسخة الويب محليًا نفّذ `npm run web`، ثم افتح الرابط الظاهر في المتصفح وسجّل الدخول بحساب Supabase.
4. لتصدير ملفات الموقع الثابتة إلى مجلد `dist` نفّذ `npm run web:build`. ارفع ملفات المشروع إلى مستودع GitHub للعمل عليه، ولا ترفع ملف `.env` أو بيانات الدخول الحقيقية.

بيانات المعاينة اصطناعية ومحلية على الجهاز. لا تستخدمها لإدخال أرقام قومية أو صور بطاقات أو بيانات عملاء حقيقية، ولا تنتقل الطلبات منها بين الأجهزة.

## إعداد Supabase قبل استخدام بيانات حقيقية

1. أنشئ مشروع Supabase، ثم انسخ `.env.example` إلى `.env` وأدخل عنوان المشروع و`anon key` فقط في متغيرات `EXPO_PUBLIC_`.
2. طبّق ملفات `supabase/migrations/` بالترتيب الزمني، أو نفّذ `npx supabase db push` بعد ربط المشروع. يحتاج إنشاء الحسابات إلى صلاحيات `service_role` المحددة في الترحيل `20261117040000_account_creation_service_role_grants.sql`.
3. أنشئ أول مستخدم إدارة من Auth، ثم أضف سجله إلى `public.profiles` باستخدام قالب `supabase/seed.sql`.
4. ثبّت Supabase CLI وسجّل الدخول، ثم اربط المشروع وانشر Edge Function:

   ```sh
   npx supabase link --project-ref YOUR_PROJECT_REF
   npx supabase functions deploy admin-create-account
   npx supabase functions deploy admin-manage-courier
   npx supabase functions deploy admin-manage-account
   ```

   وظيفتا `admin-create-account` و`admin-manage-account` تتحققان بنفسيهما من جلسة المستخدم ودور الإدارة؛ لا تزل فحوص `Authorization` و`auth.getUser()` وصلاحية `admin` مع `verify_jwt = false`. المفتاح `service_role` يبقى في بيئة Supabase فقط ولا يوضع في التطبيق أو ملفات `.env` المرسلة للأجهزة.
5. أنشئ حسابات المندوبين والمطاعم وموظفي الدعم من حساب الإدارة. كلمة المرور المؤقتة تظهر مرة واحدة؛ أرسلها لصاحب الحساب بقناة آمنة.
6. في Supabase، افتح **Authentication > URL Configuration** وأضف رابط الاستعادة `https://michealyonan.github.io/delivery-operations/reset-password` إلى **Redirect URLs**. من صفحة الدخول يمكن طلب رابط استعادة إلى البريد؛ يعمل الرابط بعد السماح بعنوان إعادة التوجيه.

## الدعم الفني

- يستطيع المندوب والمطعم فتح محادثة نصية مع فريق الدعم، وربطها بأحد طلباتهما لتسهيل التشخيص.
- تظهر محادثات الدعم في صندوق موحد؛ يستطيع موظف الدعم استلام المحادثة والرد وتحديث حالتها إلى «تم الحل». إذا أرسل صاحب الطلب رسالة لاحقًا، تعود المحادثة تلقائيًا إلى قائمة الحالات الجديدة.
- ينشئ المسؤول حسابات موظفي الدعم من «صندوق الدعم الفني». لا يوجد تسجيل عام لموظفي الدعم. الرسائل والحالات تتحدث لحظيًا عند الاتصال، ولا يدعم الإصدار الأول إرسال المرفقات أو العمل دون إنترنت.
- بعد إضافة المشروع، طبّق ترحيلات قاعدة البيانات بالترتيب الزمني، بما فيها `20261117020000_support_system.sql`، ثم أعد نشر `admin-create-account` للسماح بإنشاء حسابات الدعم.
- من قائمة حسابات المندوبين والمطاعم وفريق الدعم، تستطيع الإدارة تغيير كلمة المرور. اترك حقل كلمة المرور فارغًا ليولّد الخادم كلمة مؤقتة آمنة تظهر مرة واحدة، أو أدخل كلمة جديدة من 8 إلى 72 حرفًا. تظهر بيانات المندوب الخاصة وصور البطاقة والسيلفي للإدارة فقط، بروابط موقعة مؤقتة.

تستطيع الإدارة تحويل الطلبات غير المكتملة إلى مندوب نشط على الشيفت، بما فيها الطلبات الخارجة للتوصيل؛ عند التحويل يعود الطلب إلى خطوة الاستلام ليؤكد المندوب الجديد تسلمه. من تفاصيل الطلب تستطيع الإدارة فتح خريطة المندوبين على الشيفت ومعرفة من لديه طلب نشط، ثم إسناد الطلب أو تحويله من الخريطة. إيقاف حساب المندوب مؤقت وقابل لإعادة التفعيل، ويتطلب تحويل أو إكمال طلباته غير المنتهية أولًا.

الرقم القومي وصورة البطاقة في جدول/حاوية خاصة بصلاحية الإدارة فقط. صورة السيلفي مطلوبة عند إنشاء المندوب، وتُحفظ في حاوية خاصة لا يراها إلا المندوب صاحب الحساب والإدارة؛ تظهر للمندوب في صفحة «حسابي». لا تُفعّل المشروع ببيانات حقيقية قبل مراجعة صلاحيات المشروع وسياسة الاحتفاظ القانونية ببيانات الهوية في بلد التشغيل.

من حساب كل مطعم يمكن إدارة قائمة الأصناف وأسعارها وإيقاف الصنف مؤقتًا عند نفاده. عند إنشاء الطلب يختار المطعم الأصناف والكميات، وتحدد الإدارة رسوم التوصيل لكل طلب حسب عنوان العميل والمسافة؛ لا توجد رسوم ثابتة للمطعم ولا يستطيع المطعم إدخال إجمالي التحصيل يدويًا. لا يمكن إسناد الطلب قبل تحديد الرسوم، ويستطيع المسؤول إلغاء الطلبات التي ما زالت بانتظار المراجعة أو إرسالها تلقائيًا إلى أقرب مندوب على الشيفت بلا طلب نشط، إذا كان موقع المطعم وموقع المندوب محدثين. تُحفظ أسماء الأصناف وأسعارها كنسخة ثابتة مع الطلب حتى لا تتغير الطلبات السابقة عند تعديل القائمة. يرى المندوب المبلغ المحدد لتحصيله من العميل والمستحق دفعه للمطعم دون إدخال يدوي؛ تُسجل القيم تلقائيًا عند إتمام التوصيل.

تظهر للمندوب الطلبات النشطة فقط في قائمته الرئيسية، وتنتقل الطلبات المكتملة إلى سجل الطلبات السابقة. يظل شريط التنقل ظاهرًا داخل تفاصيل الطلب للوصول إلى الطلبات والدعم والحساب.

بعد إسناد الطلب، أمام المندوب 120 ثانية لقبوله. إذا انتهت المهلة دون قبول، يعيده النظام تلقائيًا إلى قائمة الإدارة ويظهر تنبيه بأن المندوب لم يقبله؛ تعمل جدولة قاعدة البيانات كاحتياط حتى لو أُغلق التطبيق.

تحدد الإدارة رسوم التوصيل من تفاصيل كل طلب. ومن صفحة حسابات المندوبين يمكن فتح الملف وتعديل بياناته وصوره، مراجعة أوقات الشيفت والموافقة على طلب إغلاقه، تجديد العقد لسنة من تاريخ التجديد، أو إيقافه نهائيًا مع إبقاء سجلاته. طلب البريك متاح من صفحة الدعم بمدد 5 و10 و15 و20 و30 أو 60 دقيقة؛ ويمكن للإدارة إيقاف الطلبات الجديدة وقت الضغط، مع استمرار أي بريك بدأ بالفعل حتى موعد انتهائه.

## الخرائط والموقع

- أضف مفتاح Google Maps في `GOOGLE_MAPS_API_KEY` وقت بناء تطبيق Android، واجعل له قيودًا على package `com.deliveryapp.operations` وبصمة توقيع التطبيق.
- أضف المفتاح نفسه في `EXPO_PUBLIC_GOOGLE_MAPS_ANDROID_KEY` كي تعرض الواجهة حالة إعداد الخريطة.
- يحدد المطعم موقع الفرع مرة واحدة من جهاز موجود في الفرع؛ يظهر للمندوب مع العنوان، ويمكن فتح الاتجاهات في الخرائط. إذا لم تتوفر إحداثيات، يُبحث بالعنوان.
- مشاركة موقع المندوب لا تبدأ إلا عند تشغيل الشيفت وبعد منح إذن الموقع في الخلفية. يعرض Android إشعار خدمة مستمرة أثناء المشاركة. عند إيقاف الشيفت يتوقف التتبع. إغلاق Android للتطبيق قسرًا أو إيقاف GPS/الإنترنت قد يوقف التحديث؛ الإدارة ترى وقت آخر موقع ولا تُعرضه على أنه مباشر إذا أصبح قديمًا.
- في الويب، يطلب المتصفح إذن الموقع ويُحدّثه أثناء بقاء صفحة المندوب مفتوحة فقط؛ إغلاق الصفحة يوقف التتبع. يتطلب الموقع المنشور HTTPS، بينما `localhost` صالح للتطوير. تظهر خريطة الإدارة على الويب باستخدام خرائط OpenStreetMap دون مفتاح Google، وتظل خريطة Android بحاجة إلى إعداد مفتاحها.
- يحتاج التتبع في الخلفية إلى development build؛ Expo Go معاينة للواجهات وليس اختبارًا كافيًا لهذا السلوك.

لإنشاء development build على السحابة، جهّز حساب Expo ومفتاح الخرائط ثم نفّذ `npx eas-cli@latest build --profile development --platform android`. البناء المحلي باستخدام `npx expo run:android` يحتاج Android SDK وJava/JDK.

## تسجيل الدخول

يستخدم MVP البريد الإلكتروني وكلمة مرور مؤقتة. رقم المندوب الثابت (مثل `CR-000001`) يُولّد من قاعدة البيانات ولا يرتبط بالرقم القومي. رقم التليفون محفوظ للاتصال، ويظهر للمطعم صاحب الطلب فقط بعد قبول المندوب له.
